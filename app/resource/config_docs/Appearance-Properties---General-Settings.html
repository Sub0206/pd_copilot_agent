Call Javascript on Client

Used to call a JavaScript function in the client browser session. 

The Function Type Target provides the method name as well as a list of parameters to be passed to it.  Parameters can be literal values or Q-tags for variable data. 

Any parameters that are presented as Q-tags (Q_BBBBB_SS) will be replaced with the value from the corresponding Question’s applicable View Item in the active Detail View. 

The Function Type will support two JavaScript name spaces PW.actionJS and PW.publicAPI.  Any other namespace, or a missing namespace will cause an error message to be displayed.  "The configured JavaScript namespace does not exist or is not a function. Check configuration." 

Examples:

PW.publicAPI.navigateToCustomer(Q_30000_97) 


PW.publicAPI.launchNewQuote(Q_30000_1) 


PW.publicAPI.navigateToWMTask(Q_30000_41,true)

Allocate NSF

The parent detail is updated by; increase appliedAmt by the sum of the selected rows that have a status of Pending, decrease remainingBalance by the same amount (via a specifically coded JS executed upon clicking this button).  The page will be submitted and the page will be refreshed to show the updated values if successful.   

Updates selected occurrences to a status of "Applied" where the statusCode=Pending.  Any selected occurrences where the status is anything other than Pending will lose the selection status. 

Via Configuration, the Remittance status will be closed when the remaining balance equals 0.  Also, the related Receivables will be updated using the AllocateReceivable Internal Method via a configured Action call. 

UnAllocate NSFThe parent detail is updated by; decreasing appliedAmt by the sum of the selected rows that have a status of Applied and increasing remainingBalance by the same amount (via a specifically coded JS executed upon clicking this button).  The page will be submitted and the page will be refreshed to show the updated values if successful.   

The selected rows where the statusCode = Applied will be copied to create a new occurrence(s) where the statusCode will be set to Pending.  The same set of selected row will have the removalCode set to "U" and the removalTS will be set to the current date/time. 

Via Configuration, the Remittance status will be set to Pending.  Also, the related Receivables will be updated using the UnallocateReceivable Internal Method via a configured Action call.

Remove Staged Transaction

Updates the Staging table indicating that a record is removed, if the Record Type of the record = "O" (Original), the Removed Indicator is set to "Y"; or if a record is anything other than Record Type = "O" (Original), the record is physically deleted.  After successful completion, the user is returned back to the previous Search List View

Supports both Single and Multi-Select Lists

Un-Remove Staged Transaction

Updates the Staging table record by changing the Removed Indicator from "Y" to "N". After successful completion, the user is returned back to the previous Search List View

Supports both Single and Multi-Select Lists

Post Staging Transaction

Initiates posting of the staging records, the system will attempt to post all the records  with Staging Status "INITIAL" or "FAILED" and Removed Ind = "N" in order of Account, Policy and Transaction Sequence order. If the Search List is set to be a multi-select list, the Posting will ONLY take place on records that meet the above criteria AND are selected occurrences in the List

Supports both Single and Multi-Select Lists
