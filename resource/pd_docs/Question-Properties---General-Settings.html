Answer Source

Always applicable and required

Native (Default)This is a generic question typically answered by the User. The answer value for this question does not come from the answer to another question or from the Code property of reference or product entity occurrences.

LinkedThe answer to this question will be selected from the Value property of a Reference Entity or Product Entity occurrence. Linked questions create a relationship between the linked entity occurrence and the occurrence on the transaction that allows additional capabilities like obtaining other information from the linked occurrence to function.

DerivedThe answer to this question will always match the answer to another question on the policy (must be a question on the same entity as this question or on a parent entity within the policy structure.) or from a linked occurrence identified by a linked question on the same entity. This answer may or may not be stored.

DefaultedThe initial answer to this question will be set to the answer of another question on the policy (must be a question on the same entity as this question or on a parent entity within the policy structure.) or from a linked occurrence identified by a linked question on the same entity.

SharedThis question will share answer options with another question within another entity (must be a question on a different entity as this question or on a child entity within the policy structure.). Appearance properties will not be shared with the original question.

GuestThe answer for this question actually belongs to the "host" question associated with the Guest question. Any answer provided for the host question will appear in any Guest usages and changing the answer on the Guest will also change the answer in the host question. Please note: The host question must be defined on a parent entity within the policy structure.(not applicable when B-Tag = 30000)

Secondary ParentThis question will contain the identifier of the secondary parent occurrence for this entity.

Multi ValueContains each value from a targeted question on an (usually multiple occurrence) entity Multi-Value is usually defined for usage in dependencies and is never stored (always derived). E.g. used for querying all vehicle types or garaging states on a policy.

SessionIndicates that the source of the answer for the question is from the current session and is not a persisted part of the policy transaction like other answers. Requires that the User specify a specific "Session Variable" that will be referenced or updated.

Policy FactIndicates that the source of the answer for the question is from a Policy Fact and is not a persisted part of the policy transaction like other answers. Contains information about the state of the overall policy (cancellation effective date or renewal effective date) rather than just information from the current transaction.

Filter ExpressionProvides the ability to put a filter condition on the Question for applicability processing (before dependency processing).

Help Text:

There will be a large text area for the input of the filtering values (4000 chars). Values may be entered in a single line or put on separate lines for ease of reading (Best Practice) as seen in the example. The filtering values may include:

Entry

Description

Code1

The broader level filtering value; e.g. Industry Segment Type Code

Code2

The finer level filtering value; e.g. Smart Classification Code

+

Plus sign: Finer level value inclusion

-

Minus sign: Finer level value exclusion

|

Pipe character: Broad level ending separator

,

Comma: Finer level separator for multiple instances

Syntax Example:
     Code1A+Code2A,Code2B,Code2C|
     Code1B-Code2G,Code2H|
     Code1C|
     Code1D+Code2J|

The example represents a Question Version that has filtering based on four groups for Code1. The Question Version will remain if the following is true:
     Code1 has a value Code1A and Code2 has a value of Code2A or Code2B or Code2C OR
     Code1 has a value Code1B and Code2 has a value other than Code2G or Code2H OR
     Code1 has a value Code1C OR
     Code1 has a value Code1D and Code2 has a value of Code2J

Example:
     02+E32,Q27,X67|
     04-X48,X50|
     06|
     14+E36|

Page example:
Literal with the formatting information will be included above the text box.
     Syntax is repeating groups of ('Primary Filtering Criteria', [(+ or-) 'Secondary Filtering Criteria' [teams:, 'Secondary Filtering Criteria' ... ]], |)
     | is needed between Primary Filtering Criteria if more than one Primary Filtering Criteria is used.
     If Secondary Filtering Criteria is used, the + (include) or - (exclude) must follow the Primary Filtering Criteria.
     , is needed between Secondary Filtering Criteria if more than one Secondary Filtering Criteria is used.


Clicking Submit, the syntax of the values will be verified, checking for:
     Code1 can not be duplicated within a view item filter, there can only be one group for each Code1.
     Each group must end with |.
     If + or - follow Code1 there should be one or more comma separated entries for Code2 before encountering a |.
     Use of other special characters.

     Not included in the verification - valid values for Code1 and Code2.

If an error is encountered a message box will display as: "Please check the filtering values syntax."

Applicable when Primary and Secondary Q-tags are present on the Contract Entity Page AND the Answer Source <> Multi-Value, Session, Guest, OR Policy Fact.
