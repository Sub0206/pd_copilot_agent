CoreSuite NAPC : Coverage Package Caching for QuickQuote Internal Method

Created by Former user on Oct 25, 2019

Description

Description This method will begin by getting specific exception factor values from the policy (state and coverage package name), these will be used to generate a key.  The coverage package cache will then be interrogated to find a matching Coverage Package for the key. 
  • If the key is not found then coverage package creation continues as usual by performing Rule Reapplication, at the end of which the package data is stored in the cache with the previously generated key for later reuse. 
  • If a matching coverage package is found using the key then the coverage package is created by copying the data to the policy for each of the Vehicle occurrences, this process is significantly faster than performing Rule Reapplication.  
    The method uses a set of Views defined in an Interface to apply the configured rules from the Views to the policy transaction, it is the outcome of this process that generates the data for the cache. 
Constraints Must be executed from within a Policy Transaction context. 
The data stored in the cache cannot vary by anything other than the data used to create the key, specifically state and coverage package name, the set of data received must be exactly the same at all times for these specific factors. i.e, if a default value has to vary by Drivers Age and that value is for a default selected coverage on the Basic package then the cached data could be incorrect.  If additional data is needed for the key, dependency values or other exception factors for example, then a further enhancement would be required. 
The coverage package data is required to be consistent for all Vehicle (30006) occurrences. i.e, if Vehicle 1 is leased, and Vehicle 2 is owned, then both must still receive the same set of coverages with the same initial default values. If a dependency condition exists to modify the coverages applicability based on the lease versus owned scenario above, the data retrieved from the cache would be incorrect for one of the vehicles (depending on the Vehicle data that originally populated the cache). Only a single collection of Vehicle coverage values are stored and are reused on all Vehicles, if data needs to be cached to support Vehicle level variations then a further enhancement would be required. 
Computation routines on View Item Version Variations, Session Questions and Guest Questions are not supported and can lead to incorrect data being populated in the cache, or retrieved from the cache. 
Suggested Dependencies None 
Notes This method is not typically used by itself as an action, but as a step in a more complex Policy Action.  The cache will not be interrogated or populated if the application level property 'amIPrototyping' is set to Y, instead Rule Reapplication will be performed at all times.
