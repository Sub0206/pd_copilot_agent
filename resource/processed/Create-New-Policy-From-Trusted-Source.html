CoreSuite NAPC : Create New Policy From Trusted Source

Created by Former user on Oct 25, 2019

Description

Description This method accepts update XML and handles the processing of it in the following way: 
  • The Update XML will be processed using Standard XML Upload processing. A detail view should be configured for the Policy Entity (30000); the name of this view will be specified as an attribute to this method. The processing of this view will create the basic policy occurrence. The policy occurrence can potentially be further processed during the second pass using the Trusted Source Upload mechanism. 
  • The Update XML will then be processed via Trusted Source Upload. Enhancement 526 provides details of this functionality and will not be re-described here.
Constraints See the next section for restrictions and limitations imposed by this method. 
Suggested Dependencies None 
Notes This method can be used by itself as the only Step in an Action, or as a single Step in a more complex Policy Action. 

Restrictions and Limitations

Below are constraints that are specific to this internal method, further constraints are imposed by Trusted Source and these also need to be taken into account, for details pf these limitations please read Enhancement 526 - Trusted Source Upload.

First Pass - Policy Creation

  • The POLICY_VIEW attribute only allows a single view to be specified, this limits the initial policy creation process to that single view. If further information needs to be added beyond this view and that which Trusted Source processing allows then an additional post-processing step may be necessary.
  • View Items of type Action are not processed.

Second Pass - Policy Update from Trusted Source

  • Occurrences are created in the entity order in which they appear in the interface. This has consequences for secondary parents and should be taken into consideration when creating the interface, the following ordering conditions should be observed.
  1. Entities that might be parents but which do not reference a secondary parent themselves
  2. Entities that might be parents and which reference a secondary parent
  3. Entities that will not be parents but which reference a secondary parent

NOTE: In the case of cyclic secondary parent references, in which two entities are secondary parents of one another, it may be necessary to create a second xml view to establish the reciprocative links. This is because Trusted Source does not reprocess the views automatically for performance reasons.
