Store XML in Policy Report Staging Table

Description

This method takes the XML provided to the Step and after any Forward XSL processes it, stores it in the XML Staging table in the database.

All calls to this method will add a record to the table. There will be no matching of existing records to the new record being added. If an interpretation of the data between transaction snapshots is required it is incumbent on the downstream process that is processing the provided data to apply any associated aggregation or reconciliation rules.

This method is supported in both an online context and via the SOAP Gateway. When used in an online context the Step should generate the XML to be stored. When used via the SOAP Gateway the configuration could be set to Accept Input XML and then transform and store it.

See Enhancement 997 for full treatment of the data model, table definitions, and xml schema.

Supported Action TypeStandard
ConstraintsMust be executed from within a Policy Transaction context.
Suggested DependenciesNone
NotesThe method simply puts whatever XML is provided into the Staging table. The XML provided can be validated against a Reporting Schema if one is specified in the Application Property and the system is in Test Mode. Since the load of the data from the XML Staging table to a downstream reporting table or process happens after the method returns to the calling Action, any condition in which the XML cannot be loaded, in total or in part, into the Reporting Tables, no return code will alert the user that the transaction may remain solely in the Staging table or be missing elements.


XML Usage

Generate from DB, Accept XML for Update, or Reuse XML from Prior Step are all supported options for the XML required for this method.
