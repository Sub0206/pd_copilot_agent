relatedCustomerQtagsRequired

Valid Q-tags that are linked to a Customer Occurrence

Example:

relatedCustomerQtags=Q_30010_27,Q_30000_97

A comma separated list of Q-tags that should be used to identify additional linked Customer occurrences on related policies for use in populating the drop-down.  Any Q tag included must be a Customer Link Question.

 

This property was previously used for dual purposes and is now being focused solely on building the list of Operators for the assignment drop-down on the page.		 
updateCustomerQtagRequired

A single valid Q-tag that is linked to a Customer Occurrence

Example:

updateCustomerQtag=Q_30010_27

This property provides the Customer Link Question that should be populated with the Customer ID in the upload XML that is created to add a Customer to a policy in the household.

The value in this property is used to also identify the entity whose XML tag is used to assemble the upload XML for any operator add or update on a policy as part of the page submit.

 

Ideally, the Q tag in this property should also appear in the list in the relatedCustomerQtags property.		 
addOperatorSourceVTagRequired

A valid View that corresponds to the same entity as the entity in the Question identified by the updateCustomerQtag property value.

Example:

addOperatorSourceVTag= vehicleUsageXML

Identifies a View whose View Items will be used to retrieve Contract Answers from the source operator occurrence to be fed into the upload XML used to add an Operator occurrence in a different policy.

 

The View Type is irrelevant but an XML View that is specific to the page is recommended.  Reusing a large Detail View, like operator Detail, may provide other values in the upload XML that may not be desired like Continue process Questions, computed values, items retrieved by service calls, etc.
