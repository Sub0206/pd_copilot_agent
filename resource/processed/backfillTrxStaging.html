CoreSuite NAPC : backfillTrxStaging

Created by Jagadish Rotti, last modified on Oct 23, 2020

Backfill Transaction Staging Table

Description

Uses the current Account in context to identify any associated Policy Transactions on the Account and verifies that each one is reflected in the BM_TRANSACTION_STAGING table and associated with the Account. 

Transactions that have the Billing Transaction Indicator in BILLING_TRX_IND, 30006-112, set to Y will be excluded.  Records with N or null values will be included.

Transactions will be processed in order by TRANSACTION_SEQ_NUMBER from the V_BM_POLICY_TRAN view.

The process will validate the presence of an Account in context and get the Policy Transactions on the Billing Account, across all Policies on the Account, from the V_BM_POLICY_TRAN view.  The process will verify whether each transaction exists in the staging table.  If it exists, the process will do nothing with that transaction.  If it does not exist, the transaction will be added to the table.  The data captured in the staging table will be based upon the mapping below with the relevant source values coming from the record on the V_BM_POLICY_TRAN view.

All transactions backfilled by the method will be marked as POSTED and will be considered final.

Supported Action Type

Standard

Constraints

The method has no constraints other than that it requires an existing Account be in context.  It uses no input XML or other input beyond the Account in context.

Suggested Dependencies

Should only be used after the contents of an entire Account has been uploaded. 

Notes

Can be used to sync up the policy transaction records with the current state of the account.

Intended for use from a Billing Account Conversion Upload Action.

Should not be called on a routine basis as overheard is involved for the validation of the transactions against the table.


BM_TRANSACTION_STAGING Table Mapping

When a new record is added to the BM_TRANSACTION_STAGING table, the data included will be taken from the V_BM_POLICY_TRAN view that assembles information about the transaction and allows the identifiers to connect it to the parent Policy.  Some Policy data will be sourced from the V_BM_POLICY view as well where it corresponds to the selected transaction.
