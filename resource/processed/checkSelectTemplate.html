Check Select Occurrence

The Check Select occurrence uses the Check Select Child Properties, the Standard Detail Properties for Parent Detail (shared between DLD & UPD schedules when both selected), the List Properties, the Detail Properties, and/or the Updateable List if Updateable List Schedule is included.


Check Select Child Properties

The Standard Check Select Child Properties are defined below:
Property Parameter
Usage
Example Values
Description
Comments
presentationTypeRequiredMust be set to CheckSelectChild
Example:
presentationType= CheckSelectChild		Indicates that this properties file is for a CheckSelectChild presentation type. 
individualDetailNameRequiredPolicy V-tag
Example:
individualDetailName=policyCoveragesDT		Indicates the V-tag that should be used to process the policy occurrence. Note that this V-tag must contain the initialCodeQuestion as defined in the CheckSelectParent properties file and this question must be the first View Item in the view. 
emptyListMessageOptionalText
Example:
emptyListMessage=This policy does not qualify for any Property coverages.		Literal displayed to the user when there are no Product Occurrences returned from the Product List View. 
defaultScheduledItemHyperlinkTextRequiredText
Example:
defaultScheduledItemHyperlinkText=Click here to view the scheduled items list for this coverage		Literal displayed to the user if a Product Occurrence indicates that the Product Occurrence Structure is an DLD or UPD. 
requiredOccurrenceTextRequiredText
Example:
requiredOccurrenceText =REQUIRES:		Literal that is used to prefix the Product Occurrence Short Name of the Parent Product Occurrence that must be selected before the current Product Occurrence can be selected (i.e. Parent Coverage must be selected before the child Coverage can be selected). 
fetchDetailViewForSelectedItemsOnlyOptionalY,N
Example:
fetchDetailViewForSelectedItemsOnly=Y		Indicates if the occurrence details should be loaded as needed (Y) or if they should all be loaded on load of page (N - Default). See enhancement 973 for more details. 
processImpactedProductOccurrencesOptionalY,N
Example:
processImpactedProductOccurrences=Y		Indicates that upon submit of the tab, changes to the current occurrences on the tab may impact the applicability of the other occurrences on other tabs. If set to Y, then the related product occurrence list will be scanned to see if there are any new occurrences that should be added (because an occurrence is now marked as "required") or removed because the occurrence is no longer applicable (applicable = N or because a parent occurrence was removed).

If this property is set to N, then the Product Occurrence list will NOT be processed upon submit of the tab.

Default = Y to provide backwards compatibility which always processed the Product Occurrence list upon submit.

Note that prior to 8.1.4, this process was executed on both a tab loading an unload. With 8.1.4, this process will ONLY be executed on unload of the tab.
