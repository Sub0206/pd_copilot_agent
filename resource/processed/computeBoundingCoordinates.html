CoreSuite NAPC : computeBoundingCoordinates

Created by Jagadish Rotti, last modified by Former user on Nov 05, 2019

Compute Bounding Coordinates (Detail View Only)

Description

This method accepts four questions via Attributes to be used as input to a computation that computes values for five output questions, also specified in Attributes, that represent a set of bounding coordinates for the provided input Latitude, Longitude, and Radius value.

The values for those questions can then be used from within a Search Detail Adaptik Unit to drive a search that returns information related to items related to addresses within the circle defined by the central point and radius.

Latitude and Longitude must be specified in radians, while the Radius of interest should be in whatever Unit is relevant to the project.  The unit of interest is also passed to the method as a configured Attribute.

Supported Action Type

Detail View

Constraints

Can only be used to update questions present in the active Detail View, from questions present in the active Detail View.

Suggested Dependencies

None

Notes

Used specifically to support geocoordinate queries that identify geolocations within a specified radius of a given set of geocoordinates.

The Computation

The goal of the computation is to provide an ability to identify a set of bounding coordinates that can be used to draw a box around the circle of interest defined by the input coordinates and radius.  This allows more efficient usage of the computing and database resources by eliminating a large percentage of the candidate matches by finding them to be outside the set of bounding coordinates.


In order to determine the bounding coordinates, one must first find the angular radius of the query circle.  This formula relies on the fact that the Earth is a sphere with a radius of 6371 km or 3963 mi as defined by the provided UNIT Attribute.

r = [Radius value in km]/(6371 km) or

r = [Radius value in mi]/(3963 mi)



Minimum and maximum latitude define the farthest points north and south of the central point.



Computing the minimum and maximum latitude is accomplished by subtracting and adding, respectively, the angular radius, from the latitude of the center of the circle.  Any points not within these latitude values are automatically outside the circle and can be discounted without further processing.


Computing the minimum and maximum longitude is not as straight forward due to the way the longitude lines converge as they move away from the equator.  The latitude for the min and max longitude values will not match the latitude of the central point.  It will be slightly closer to the pole due to the curvature of the Earth.  That factors into the formula below to compute the offset for the min and max longitude that defines the bounding borders around the circle of interest.

Δlon = arcsin(sin([angular radius])/cos([central latitude]))


Once the offset has been computed, the minimum and maximum longitudes can be calculated.

lonmin = [central/input longitude] - Δlon

lonmax = [central/input longitude] + Δlon

In reality, the Longitude lines would be curved, but this illustration is included only to illustrate the notion of bounding coordinates.  Using these min and max values you can eliminate most addresses without having to do any more complicated WHERE clause analysis in the SQL query related to the circle being a circle.


 


Once the computation has derived the min and max coordinate values, those values will be used to update the specified Questions in the Active Detail View.
