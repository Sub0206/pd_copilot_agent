Create New Policy Transaction

This is an upload method and is described more fully in the Upload User Guide chapters.

DescriptionCreates a new policy transaction on an existing policy based upon the instructions passed in as Update XML using a specified interface (I-Tag) provided on the invoking Step, and sets that policy transaction as the current context for any subsequent Steps.
This method is used to create new policy transactions for existing policies e.g. policy change or cancellation. Policy context (Master Contract) is established using information (MC_ID) resident in the update XML or Action Step online context.
PolicyWriter employs a set of rules that determines what transactions may be created for a policy at any given time based upon the condition of the policy. When the creation of a new policy transaction is requested, these rules will also be employed to validate that the requested transaction is permitted given the condition of the policy.
Examples of this kind of rule include:
  • Creating a new policy with a transaction type other than conversion, rewriter or any other new business like transaction.
  • Creating a Policy Change for a Canceled policy
  • Creating a Renew for a policy that has a Non-Renew on it already
  • Creating a Policy Change whose effective date lies outside the lifetime of the policy
    Additionally, Dependencies on Transaction Types and Subtypes as well as other configuration choices may impact what transactions may be created at any given point on a policy. Special logic that is tied to the Transaction Type being created may also be applied. For example, a Rewrite or Conversion may employ PolicyWriter's grandfathering logic to accept the information provided as if the policy already existed in the system.

XML Usage

This method requires Update XML to provide information to the new transaction. XML- Use should be Accept XML for Update.

Attributes

The Create New Policy Transaction internal method also requires the use of one Attribute. The single Attribute must exist even if it contains no Value. The Attribute specifies any additional Views which should be marked as having been visited (similar to marking the pages as having been visited) as a result of the Upload. If no additional Views need to be marked the Attribute must still be included with an empty value.
