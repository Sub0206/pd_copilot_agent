Duplicate Occurrence Check

DescriptionThis method will check to see if there are any duplicate occurrences using the Question Occurrence Identifiers. A duplicate occurrence is defined as an occurrence under the same parent that has matching answers for the Occurrence Identifiers specified on the Questions of that Entity.
For example if the model has Policy, Vehicle, Additional Interest and the same Additional Interest was added to 2 different vehicles, then this would pass as there are no duplicates under the same parent. If the same Additional Interest was added under one vehicle, this would fail as this is a duplicate under the same parent.
If duplicate occurrences are found, a set of occurrences will be stored in a similar manner as Completeness Check so that a Duplicate Error Page can be used to show the results. B-tags without occurrence identifiers will NOT be reported as errors even if specified within the Step Attributes. The Policy Entity (30000) will never be validated as there can only ever be one occurrence.
Note that when multiple occurrence identifiers are strung together, the nulls will be considered as part of the check. In the chart below, all of the following occurrences should be considered unique and should not be considered duplicate:

NotesThe Navigation Target of the Product Outcome (if there are errors) should be a Web Page Code where the errors can be displayed.
The same storage mechanism will be used for these errors as Completeness Check. Therefore, a Configurator should NOT execute this method and then Completeness Check or Wizard without first exiting to give the user the chance to correct the problems (the table will be cleared and then updated by each method).
