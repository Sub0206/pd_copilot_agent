CoreSuite NAPC : exportDataToExcelTemplateAndDisplay

Created by Former user, last modified on Dec 03, 2019

Export to Excel Spreadsheet and Display

DescriptionUses a provided Excel template to map questions and occurrences into a spreadsheet format and invokes a file download window to display the results.
The method will use the template file (.xlsm) and create a spreadsheet that contains the desired information. That spreadsheet will then be opened on the client machine via the Display Document internal method call. After that, the user can decide if they want to save it and use it for other purposes such as the basis for updates.
Occurrences will be included in the spreadsheet based upon whether or not the occurrence hierarchy filtering is applied. The current List's parent occurrence will be tracked by the page template that invokes the Action configured to call this method. That occurrence will be used to filter the list results if the Attribute is set to Yes.
This method is only supported in an online context and not via the SOAP Gateway.
ConstraintsMust be executed from within a Policy Transaction context. The Display Documents internal method must be configured in a subsequent step to actually display the document to the user.
Suggested DependenciesNone
NotesThe current page in Account Manager will remain displayed unless the Action's configuration specifies a navigation target.
The resulting spreadsheet will have the Insert Column function disabled in the exported spreadsheet to avoid the possibility of a user invalidating the relationship between the export spreadsheet and the originating template.

 

XML Usage

None

Attributes

Three Attributes are applicable for this method. The first identifies the template file to be used to provide the export instructions to the method. The second indicates the Interface that will be used to sort the occurrences before exporting them into the Excel spreadsheet. Note that the interface should contain a list view for each B-tag used in the template. The only data used from the list view will be the sorting information (sort order and ascending/descending). All other information configured in the list view will be ignored. ONLY the questions that should be used for the sort should be included in the List View and there must be one question in each List View for each entity.


The third attribute designates whether or not ancestry filtering should be applied to the information being exported. A value of N (No) will cause the export to contain all occurrences of the target entities across the transaction, regardless of the current List or Page's hierarchy. A value of Y (Yes) will include only those occurrences in the current List's ancestry as well as all child occurrences of the List's parent occurrence. Any List Filters being used on the current page would not be applied, so the list could contain more occurrences than those visible on the page.
