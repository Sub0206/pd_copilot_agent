Find Policy Transaction

DescriptionUses the parameter values specified in the Input XML to identify the policy transaction of interest on the policy to be set into context.
If no criteria is provided in the input XML, or no matching transaction is identified, the method will put the latest active issued regular-category transaction on the policy into context. If no issued transaction exists on the policy, the open new-business-like transaction will be used.
If in any case, multiple versions of an open transaction are identified by the criteria, the latest (by create date) will be selected.
Supported Action TypeStandard
ConstraintsMust be executed from within a policy context.
Suggested DependenciesNone
NotesTypically used to support Policy Inquiry using Policy Number or MC-ID only without a specific CT/Version.
Can be used to identify if a particular type of transaction has been created on the policy.
The Step will require an Interface when the XML Source is Accept for Update, but the Interface is not used by the method.

 

XML Usage

This method expects update XML that contains the parameters to be used for transaction selection. If no XML is provided then the default transaction will be set into context.

Attributes

None

Identifying the Policy Transaction to Set into Context

Only a select set of configured Questions will be available for use to identify the transaction of interest for this internal method. Transaction Effective Date (30000-143) was available as an input parameter in previous releases. Additional parameters are being added in this enhancement. The full list of available parameters and the corresponding matching rules are listed in the table below. If any other Questions are included in the input XML they will be ignored.

When multiple parameters are included in the input XML, the parameter values will be AND-ed to identify the transaction of interest. For example, if a Transaction Effective Date of 05/30/2015 and a Transaction Type of NONRENEW are both included, the method will look for a NONRENEW Type Transaction whose Transaction Effective Date is on or before 05/30/2015. A NONRENEW on that policy after that date would not be identified.

In the case where multiple transactions are identified by the provided criteria, the latest one, by Transaction Effective Date, CT-ID and Version (in that order), will be selected and set into context. If no transaction is identified by the provided criteria the latest active issued regular category transaction will be set into context and the Return Code will indicate that no transaction was identified and the default transaction is being used. If multiple versions of an open transaction are identified by the criteria, the latest (by create date) will be selected.

Because the Find process is working outside of a Configuration Version, the XML tags used to identify the search parameters in the input XML will be obtained from Base Definition rather than the Product Configuration.
