CoreSuite NAPC : findPolicyTransaction2

Created by Former user on Oct 25, 2019

Find Policy Transaction via XML


Description 

Uses the parameter values specified in the Input XML to identify the policy transaction of interest to be set into context 

The request can include information to search within the current policy context or can include policy level identifiers (policy number or MC ID) to identify the MC ID of interest for the transactional search.  If policy identifiers are included, and no policy is found, the method will fail, return an error code, and no change of context will be performed. 

If no transactional criteria is provided in the input XML, or no matching transaction is identified, the method will put the latest active issued regular-category transaction on the policy into context.  If no issued transaction exists on the policy, the open new-business-like transaction will be used. 

If in any case, multiple versions of an open transaction are identified by the criteria, the latest (by create date) will be selected.   

If a default transaction is used to initialize context, a return code will indicate that the parameters did not identify a transaction. 

Once a transaction is identified, if the transaction changes the policy or term in context, the CV selection will be executed to put the correct CV in context.  The definition of the currently executing Action will not be changed and will continue using the original image loaded when the Action began.  Any Views or Interfaces used once the CV has been updated will be taken from the new CV.  This behavior is consistent with how Renewal transactions and the Establish New CV Internal Method currently behave.

Standard  

Constraints 

 

Suggested Dependencies 

None 

Notes 

Can be used to navigate between related policies on the same Customer or household. 

Can be used to identify if a particular type of transaction has been created on the policy. 

The Step will require an Interface when the XML Source is Accept for Update, but the Interface is not used by the method. 

 

XML Usage 

This method expects update XML that contains the parameters to be used for transaction selection.  If no XML is provided, then the default transaction will be set into context and an error returned. 

Attributes 

None 

Identifying the Policy and Transaction to Set into Context

Only a select set of configured Questions will be available for use to identify the transaction of interest for this internal method.  The full list of available parameters and the corresponding matching rules are listed in the table below.  If any other Questions are included in the input XML they will be ignored. 

When multiple parameters are included in the input XML, the parameter values will be AND-ed to identify the transaction of interest.  For example, if a Transaction Effective Date of 05/30/2018 and a Transaction Type of NONRENEW are both included, the method will look for a NONRENEW Type Transaction whose Transaction Effective Date is on or before 05/30/2018.  A NONRENEW on that policy after that date would not be identified. 

In the case where multiple transactions are identified by the provided criteria, the latest one, by Transaction Effective Date, CT-ID and Version (in that order), will be selected and set into context.  If a policy is identified, or already in context, for a request with no policy identifiers, no transaction is identified by the provided criteria the latest active issued regular category transaction will be set into context and the Return Code will indicate that no transaction was identified and the default transaction is being used.  If multiple versions of an open transaction are identified by the criteria, the latest (by create date) will be selected. 

If the identified transaction changes the policy or term in context, the CV selection will be executed to change the Usage CV in use.  The definition of the currently executing Action will not be changed and will continue using the original image loaded when the Action began.  Any Views or Interfaces used once the CV has been updated will be taken from the new CV.  This behavior is consistent with how creating Renewal transactions and the Establish New CV Internal Method currently behave. 

Because the Find process is working outside of a Configuration Version, the XML tags used to identify the search parameters in the input XML will be obtained from Base Definition rather than the Product Configuration. 

Parameter 

Behavior 

MC_ID 

XML attribute @MC_ID 

The explicit MC ID for the target policy.  If provided, any related Policy Number parameter will be ignored. 

If neither MC ID nor Policy Number are included in the parameters, the current policy context will be maintained to allow for finding transactions within the current policy. 

Policy Number (30000-160) 

The value provided should represent the policy number for the policy.   

The value will be used to find the corresponding MC ID by using it in a query against the Alternate Query table. 

If neither MC ID nor Policy Number are included in the parameters, the current policy context will be maintained to allow for finding transactions within the current policy. 

Transaction Type (30000-10) 

The value provided should represent the code value for the Transaction Type.   

A transaction will be considered a match if its value in the CT_TYPE column in the Contract Transaction table exactly matches the value provided (case-insensitive). 

Transaction Subtype (30000-11) 

The value provided should represent the code value for the Transaction SubType.   

A transaction will be considered a match if its value in the CT_SUBTYPE column in the Contract Transaction table exactly matches the value provided (case-insensitive). 

Transaction Effective Date (30000-143) 

A transaction will be considered a match if its value in the EFF_DATE column in the Contract Transaction table is prior to or the same as the value provided (date comparison). 

Process Date (30000-35) 

A transaction will be considered a match if its value in the PROCESS_DATE column in the Contract Transaction table is prior to or the same as the value provided (date comparison). 

Term Number (30000-37) 

A transaction will be considered a match if its value in the TERM_NO column in the Contract Transaction table exactly matches the value provided (numeric comparison). 

Transaction Stage (30000-39) 

A transaction will be considered a match if its value in the STAGE column in the Contract Transaction table is less than or equal to the value provided. 

Transaction Status (30000-40) 

The value provided should represent the code value for the Transaction Status.   

A transaction will be considered a match if its value in the TR_STATUS column in the Contract Transaction table exactly matches the value provided (case-insensitive). 

If no value for this parameter is included, only transactions with an issued (Closed – C) value will be considered. 

Agent Code (30000-41) 

A transaction will be considered a match if its value in the AGENT_CODE column in the Contract Transaction table exactly matches the value provided (case-insensitive). 

Underwriting Date Timestamp (30000-152) 

A transaction will be considered a match if its value in the UNDERWRITING_DATE column in the Contract Transaction table is prior to or the same as the value provided (date comparison). 

Rating Date Timestamp (30000-45) 

A transaction will be considered a match if its value in the RATING_DATE column in the Contract Transaction table is prior to or the same as the value provided (date comparison). 

Policy Term Effective Date (30000-34) 

A transaction will be considered a match if its value in the POLICY_EFFECTIVE_DATE column in the Contract Transaction table is prior to or the same as the value provided (date comparison). 

Policy Term Expiration  (30000-142) 

A transaction will be considered a match if its value in the POLICY_EXPIRATION_DATE column in the Contract Transaction table is prior to or the same as the value provided (date comparison). 

Referral Status Code (30000-38) 

The value provided should represent the code value for the Referral Status Code.   

A transaction will be considered a match if its value in the REFERRAL_STATUS column in the Contract Transaction table exactly matches the value provided (case-insensitive).
