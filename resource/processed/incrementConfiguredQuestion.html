Increment Configured Question

DescriptionThe method will allow a specified question, identified by the Q-tag in the first Step Attribute, to be updated by applying an increment, specified by the second Step Attribute, to the largest value found for the question across all of transactions within the transactional scope identified by the third and fourth Step Attributes.
If the question does not have an answer on the transaction, a new answer will be created for the question.
If no existing answers are found within the specified transactional scope, the question's value will be set equal to the increment since it will consider the largest previous value to be zero.
No consideration is given for marking any Views as visited for the purposes of Rule Reapplication or Sideways Impact processing when using this method, and it will not cause the execution of Rule Reapplication or Sideways Impact processing as a result of changing the question's value.
Supported Action TypeStandard
ConstraintsMust be executed from within a Policy Transaction context.

Errors/Warnings

  • This internal method will only work on questions whose Answer Source is Native and Data Type is Integer, Real, or Year. The method will not be doing any data type conversion for Text, Dates or other data types. If a question of some other data type is configured for use, the results will be uncertain.
  • This method does not use a View to process the answer, so it will not make use of capabilities such as View Item versions, Rule Reapplication sensitivity, Variations, or Exceptions to alter any configuration of the question. If any such mechanisms are configured for the question, they will be ignored in favor of the base version of the question (None Exception; Variation 1).
  • Updates using this method will not trigger sideways impact processing, nor will they mark any View/Page as visited for Rule Reapplication processing.
  • Updates using this method will impact Contract Answers only. There is no support for using this method to update dual fields (those that also appear in the contract_transaction table).
  • It is recommended that any question used with this method for the purposes of identifying a transaction be configured as a Q-Group 0 question to support correct processing on Flag and Event-type transactions.
