CoreSuite NAPC : initializeValuesFromPrevTrans

Created by Former user, last modified on Dec 05, 2019

Initialize Values from Prev. Transaction

DescriptionThis method will reset contract answers for a configured list of questions on the current transaction to the values they had on the previous transaction. If a contract answer does not exist already on the current transaction, one will be created. If the question does not have an answer on the previous transaction, no new answer will be created for the question on the current transaction.
If the question being updated is a dual field (meaning it exists as a column on contract_transaction too), then both the contract answer and the table value will be updated by the method.
The values set by this method will be used in the transaction as the starting values for the questions. If the question already had changes applied those changes will be lost. The answers obtained by this method will appear as the "before" value for the question with the exception of Q-group 0 questions which will continue to be shown as new values on the transaction.
A repeating group of attributes will be accepted for this method. Each attribute will specify a question whose value should be sourced from the previous transaction.
Enforce Stage and any literal or other component on the answer is also copied from the previous transaction's answer and used for the current transaction.
Supported Action TypeStandard
ConstraintsIf the transaction is a New Business-like transaction (NB, CONV, and REWRITE) where there is no previous transaction, the method will do nothing and return an error indication.
If the question's entity is not Policy, then the answers from the previous transaction will be taken from the corresponding occurrence (using occurrence ID) and all occurrences' answers will be initialized or reset. Any occurrences that did not exist in the previous transaction will not have their question values reset.
Suggested DependenciesNone
NotesSince there is no View processing involved with this method, all occurrences will be impacted if it is used for a repeating child entity. All occurrences that exist on the previous transaction will have their answers retrieved from that previous transaction. There will be no consideration for applicability in the current transaction although it may already have been established in the previous transaction. Applicability could be enforced using Rule Reapplication after this method executes.
