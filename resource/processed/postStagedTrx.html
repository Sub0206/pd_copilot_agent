CoreSuite NAPC : postStagedTrx

Created by Jagadish Rotti on Oct 23, 2020

Post Staged Transactions

Description

Uses the current Account in context to identify any associated staged, but not posted, Policy Transactions on BM_TRANSACTION_STAGING table and associated with the Account.  Those will be identified by a STAGING_STATUS of INITIAL and sorted in CREATE_TIMESTAMP and Transaction Sequence order.  If a Policy already has any ERROR transaction records [MLM1] in the table, the Policy’s transactions will not be included in the processing.

The method will validate the presence of an Account in context and get the staged Transactions on the Billing Account, across all Policies on the Account, from the BM_TRANSACTION_STAGING table.  For each transaction identified the method will take the TRX_XML and pass it to the configured Action identified by the ACTION Attribute on the Step.

The Action will process the data in the XML and provide a return code indicating if the processing was successful or not.  If the Action returns success (1), the record in the staging table will be updated with a STAGING STATUS of POSTED.  The Return Code from the Action controls the update of the Staging record status as it currently does for transactions posted immediately. 

If any transaction is marked as ERROR for a Policy, the processing of any other transactions stops for that Policy [MLM2] and a Return Code indicates an error occurred.   

This method triggers MC-level locking on the Account, but each transaction will be committed when the invoked Action completes for the transaction.

Supported Action Type

Standard

Constraints

The method has no constraints other than that it requires an existing Account be in context.  It uses no input XML or other input beyond the Account in context.

Suggested Dependencies

None 

Notes

Should be used thoughtfully as an overall approach to managing large accounts. 

Policy configuration of the Billing interface will need to add the custom XML tags to the staging xml to figure out when to mark pay plan changes and due day changes.
