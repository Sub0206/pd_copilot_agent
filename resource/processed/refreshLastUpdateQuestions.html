Refresh Last Update Questions

DescriptionThis method forces an update of the question answers associated with Questions configured as Last Update questions. If the answers for those questions have not been changed in the current transaction, the answers are refreshed from the latest, by process date, active issued transaction of any category.

This method performs the following steps:
  1. The latest (by Process Date) active issued transaction (of any category) is selected. If that transaction is the same as the transaction identified by the prev_ct on the current transaction, no further processing is necessary because the answers will already contain the latest values so the method will not process any further steps.
  2. If a different transaction is identified as the latest transaction, then the contract answers from the current transaction will be joined against the CQU table using the CV from the new transaction to identify any relevant Last Update category questions in the transaction.
  3. For each question identified as a Last Update type question in the step above, the before and after IDs will be checked against the corresponding before and after IDs from the same question in the identified latest transaction, if they match, no further action is required and the method will perform no further steps.
  4. If the before and after IDs do not match, then the before and after IDs on the current transaction must be adjusted (which may require creating a new cts_id and copying all the relevant CTE records) based upon the following logic:

    a. If the before and after IDs on the current transaction are equal (no changes made to the information in this transaction) they both will be set to contain the after ID from the latest transaction.

    b. If the before and after IDs are not equal (meaning the field was changed in the current transaction) the before ID will be set to contain the after ID from the latest transaction for the same question.
