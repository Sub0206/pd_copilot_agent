Restore Deleted Occurrences

DescriptionThis method will identify any items under a common, non-deleted parent occurrence that have both an added and deleted occurrence for the same logical thing (i.e. Coverage), and will resolve the identified pairs so that instead of 2 occurrences, one added and one deleted, only one occurrence will remain that will reflect any updates as changes.

The attributes include a list of questions that will absolutely retain their original answer values from the original (deleted) occurrence and are treated as an exception to the normal processing.
Supported Action TypeStandard
Constraints
  • The configurator should remember to generate new XML for the action after this method is used to ensure that the updated contents of the transaction are correctly reflected.
  • This whole process should only be used on subsequent (non-new-business-like) transactions since deleted occurrences are not tracked on new-business-like transactions.
  • This cannot be used to bring back parent/child ancestries. Only one level of entity may be treated by the method. For example, if a vehicle is deleted and its child coverages are also deleted then the vehicle is added again and the coverages also added again. The method will work correctly on the vehicle but will not bring back the coverages in the same fashion.
  • The add/delete pairs will be identified only when they have the same exact parent occurrence (by c-id). No "logical equivalency" will be used to identify parents.
Suggested DependenciesTransaction Type is NOT NB, CONV, REWRITE
NotesThis method will remove any updates that were made to the deleted occurrence after it was deleted using the facilities from enhancement 835 - Ability to store information on deleted occurrences. The updates will be reset before the occurrences are processed so that the process will use the original "before" image of the occurrence.
