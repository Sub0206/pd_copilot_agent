Send Email Message

DescriptionThis method allows the configurator to construct an email message from the contents of the policy transaction in context and queue it for delivery to the specified recipients.
Supported Action TypeStandard
ConstraintsThe input XML (after the forward XSL) must correspond to the XML Structure described below.

File attachments and embedded images are not currently supported.
Suggested DependenciesNone
NotesThis method will place an email request on the corresponding queue, but cannot track the final disposition of the email message. It will indicate whether the item was placed on the queue successfully or not, but will not provide details on whether it was sent successfully.

This method relies on three application properties to identify the email gateway URL, the (optional) user ID, and (optional) password that should be used to transmit the email.

The current implementation uses SMTP in the Email Service to transmit the email messages, but the method itself does not use the protocol and can be integrated with a Email Service that uses a different protocol in a future project.

Attachments can be included if they are sourced from configured File-type Questions. No other attachment answer source will be supported.

The file name stored as part of the File-type Question answer will be the file name used to transmit the file. NO overriding of file names will be supported.

Mime Types are required in order to transmit the file in an email and will be explicitly specified, or derived from the extension or suffix of the file name stored with the file.


XML Usage

This method requires the use of the following XML structure.

NameData TypeDescription
EmailMessagecomplexTypeRoot node of the request structure.
MessageHeadercomplexTypeContainer element for the message header elements.
FromTextProvides the email ID that should be used in the "from" aspect of the email being sent.

The email vendor being used to transmit the message may include restrictions on what email IDs can be used as the "From" ID on email message, or override the value sent with something at the account level. No validation is done by the method however.
ReplyToTextProvides the email ID that should be used in the "reply to" aspect of the email being sent.

The email vendor being used to transmit the message may include restrictions on what email IDs can be used in this component on email message. No validation is done by the method however.
TocomplexTypeContainer element for the message recipient emails.
EmailAddressTextThe possibly repeating Email Address to be used.
CccomplexTypeContainer element for the message Carbon Copy recipient emails.
EmailAddressTextThe possibly repeating Email Address to be used.
BcccomplexTypeContainer element for the message Blind Copy recipient emails.
EmailAddressTextThe possibly repeating Email Address to be used.
PriorityTextIndicates the Priority value required by the integrating vendor.

The GMail vendor utilizes an integer value with 1 as the highest priority and 5 as the lowest priority. Depending on the integrating vendor these values may change which is why the field is text and not numeric.

In the Adaptik SMTP implementation, 3 is the default value.
SendDatedateProvides the date the message was marked as sent. Not used for scheduling the message to be sent, but simply provides the information that will be shown as the Send Date on the message received by the target ID(s).

Defaults to current date if not provided.
SubjectTextThe email subject to be used for the message.
BodyTextThe body of the email message.
AttachmentscomplexTypeContainer element for one or more message file attachments
AttachmentRefIDIntegerThe Contract Answer ID of the file Question answer that contains the file

If this value is null, or if there is no file information found for the referenced contract answer, no attachment will be included in the email sent and no error or notification will be produced beyond a log file entry. This may happen in the case of a missing answer for the Question.

Attachments may only be transmitted using File-type Question answers from the Contract Answer aspects of the PolicyWriter database. No other source for file information will be supported. This means that a file must have been uploaded into a Question on the Policy Transaction before it can be used as an attachment in an email transmission.

The actual file attachment contents will not be included in this XML, but a reference to where the file is located in the database will allow the email client to retrieve the attachment information and use it to send the email to the specified client API.
@MC_IDIntegerThe Master Contract ID associated with the File Question Contract Answer
@MimeTypeTextAn optional mime type value that can be used to override any mime type that would be derived from the identified file's file name suffix/extension on the attachment in the database
Example:

<?xml version="1.0"?>
< EmailMessage>
<MessageHeader>
<From>jdoe@adaptik.com</From>
<ReplyTo>jdoe@adaptik.com</ReplyTo>
<To>
<EmailAddress>fsmith@adaptik.com</EmailAddress>
<EmailAddress>tjones@adaptik.com</EmailAddress>
</To>
<Cc>
<EmailAddress>fpresley@adaptik.com</EmailAddress>
<EmailAddress>jcash@adaptik.com</EmailAddress>
</Cc>
<Bcc>
<EmailAddress>mearley@adaptik.com</EmailAddress>
<EmailAddress>plate@adaptik.com</EmailAddress>
</Bcc>
<Priority>2</Priority>
<SendDate>2014-12-15</SendDate>
<Subject>This is a test email</Subject>
</MessageHeader>
<Body>This is a test. This is only a test. If this were a real email you would be informed of what the actual content should be and how to respond to it.</Body>
<Attachments>
<AttachmentRefID MC_ID="123400001" MimeType="text/plain">43567</AttachmentRefID>
</Attachments>
< /EmailMessage>
