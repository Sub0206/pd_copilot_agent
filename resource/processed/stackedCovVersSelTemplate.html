CoreSuite NAPC : stackedCovVersSelTemplate

Created by Susan Wilson, last modified on 20 Nov, 2019

 

The Stacked Product Occurrences with Version Selector Template uses the Custom Version Selector properties and the Custom Stacked Product Occurrence Properties that must be named and configured as follows: 


Version Selector Properties

The Standard Version Selector Properties are defined below:
Property Parameter
Usage
Example Values
Description
Comments
presentationTypeRequiredVersionSelector
Example:
presentationType=VersionSelector		Provides the Presentation type that is being instantiated 
ViewNameRequiredValid Policy List View V-Tag
Example:
ViewName=policyTabsLT		Provides the Policy List View that will be used to supply the labeling information for the Adaptive Unit. 
actionMacroRequiredValid Action Macro code
Example:
actionMacro=ratePackage		Provides the Action macro that should be run against each non-removed version while the page is being loaded.

If the Macro is not applicable by Dependency evaluation on any version, the Macro will not be run.		 
selectedVersionQtagRequiredValid Policy Question Q-tag
Example:
selectedVersionQtag=Q_30000_900		Provides the Q-tag that should be used to determine which version will be selected for the current context while the page is being loaded. This should be evaluated before the Action Macro is run against the versions and the appropriate version placed into context.

This Q-tag must be included in the list view used to label the tabs on the page. It can be hidden, but it must be included as a View Item in the list View.		 
selectedVersionValueRequiredValid Policy Question Value
Example:
selectedVersionQtag=CUSTOM		Provides the value that should be used with the Q-tag above to determine which version will be selected for the current context while the page is being loaded. The first version (numerically by version number) where the identified Q-tag contains the specified value will be selected for the current context on the page. If no versions meet the criteria, the highest version number will be selected as a default.

This should be evaluated before the Action Macro is run against the versions and the appropriate version placed into context.		 
maxVersionCntRequiredInteger
Example:
maxVersionCnt=4		Indicates the maximum number of versions that are allowed for the current context. If the established versions equal or exceed the max versions, the plus sign tab will be shown allowing the user to create a Custom version within the page. 
addVersionMacroOptionalValid Action Macro code
Example:
addVersionMacro=ratePackage		Provides the Action macro that should be run against any newly created "Custom" version created from the page.
If the Macro is not specified or not applicable by Dependency evaluation on the new version, the Macro will not be run.		 
displayTypeOptionaltabs, buttonsIndicates the renderer that should be used to display the List of versions available for selection.

buttons is the only value supported for 8.1. In 8.2 there is an enhancement candidate that will add tabs as a valid value.

rendererTypeOptionalTabularFormat

Optional field that will allow changing the renderer for the Stacked Product Occurrence Template from the standard vertical view into the new Tabular Horizontal view

If this property is not provided, the default behavior will be to use the existing vertical renderer


literalColumnWidthOptionalExample: 200px or 20rem

A value including the unit of measurement that will be used to govern the width of the first column that contains the literal.

If this value is not provided, it will default to 30rem as supplied in the base CSS theme. This can be overridden at a custom theme level if needed


maxControlColumnsOptionalExample: 4 

A numeric value to indicate the number of occurrence control columns displayed between the two arrows before scrolling is needed. Once the number of occurrences exceeds this value, the arrows will become applicable so that occurrences can be scrolled between

If not specified, this will default to 3 columns


coveragesLiteralOptionalExample: Coverages

The literal displayed in the top-left corner where the occurrences and literals intersect. 

If not specified, no text will be displayed


emptyMessageOptionalExample: There are no vehicles available

The literal text displayed in place of the Tabular Grid if there are no occurrences available to set coverage information for.  

If not specified, no text will be displayed
