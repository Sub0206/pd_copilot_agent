Update Policy Log Table

DescriptionThis method will update existing columns in the Policy Log Table for the current policy in context using Attributes that specify the specific column(s) and the values that should be set in them on the policy's row in the table. If a value is not already present in the column, a new one will be created. If there is already an existing value present, it will be updated.

A repeating group of attributes will be accepted for this method. Each attribute will specify a column and the value that should be updated. Any number of columns can be updated in a single execution of the method
Supported Action TypeStandard
ConstraintsMust be executed from within a Policy Transaction context on an issued policy.
Note that the following columns in the Policy Log Table may not be updated by this method:
  • MC_ID
  • MP_ID
  • COUNTRY
  • STATE
  • POLICY_EXPIRATION_DATE
  • RENEW_INITIATE_DATE
  • NONRENEW_DATE
  • PL_CREATE_TIMESTAMP
  • PL_UPDATE_TIMESTAMP
  • IN_FORCE_IND
  • CANCEL_EFFECTIVE_DATE

    Any attempt to update one of these columns will cause all changes made by the method to be abandoned and an error return code to be returned
Suggested DependenciesNone
NotesIf the Step Attribute Value is "CurrentDate()", or "CurrentDateTime()" the current date or timestamp is used to create the answer value.

Also, policy level questions can be used as a source of the answer to be set.
If a value of Q_30000_## is specified, then the value of the specified question will be used.

XML Usage

None

Attributes

Each Attribute specifies the column to be set and the value to be applied. 

The data type of the column (from the table definition or column name) and of the configured Attribute will be evaluated to determine any value transformation required to make the update. For example, a date in PolicyWriter is typically MM/DD/YYYY while the DBMS may require or assume a different format. As a result, if a date is used to update a timestamp column, midnight will be the time used in the update.

Data Type Transformations will be managed for the new columns which are being defined as timestamps. If a Date is to be stored, it will be converted to a timestamp. If a String is to be stored, it will be assumed to be in the MM/DD/YYYY format with or without the accompanying time components. If the data type conversion cannot be accomplished, a specific return code will be returned.

Value to be set

Can support a Q-tag, literal, null, or the current date/time methods		VariesIdentifies the Policy Log table column to be updated and specifies the value to set it to. (repeat attribute for each column value to be set)

If the Value is "CurrentDate()", or "CurrentDateTime()" the current date or timestamp is used to create the column value.

If the value confirms to the pattern Q_*, the value will be taken from the Contract Answer that corresponds to the listed Q-tag.

If the value is null, any existing value in the column will be wiped out.

Otherwise, the value specified is used directly as the value to set in the column.
